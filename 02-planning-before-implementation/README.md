# Section 02 — Planning Before Implementation

**Status:** 🔴 RED — structure only; substantive work pending.

## Purpose
Establish a repeatable discovery and planning process before implementation begins.

## Planned documents
- PROJECT-DISCOVERY.md — problem, users, context, constraints, and desired outcomes.
- CURRENT-STATE-AUDIT.md — repository, runtime, dependencies, branches, configuration, tests, and deployment audit.
- REQUIREMENTS.md — functional and non-functional requirements.
- ARCHITECTURE-OVERVIEW.md — system boundaries, components, and major decisions.
- DEPENDENCIES.md — internal/external dependencies and owners.
- ACCEPTANCE-CRITERIA.md — testable completion conditions.
- DELIVERY-PLAN.md — phases, sequencing, risks, and milestones.
- STATUS.md — evidence, blockers, and next action.

## Dependencies
Uses Section 01's identity, user, value, and scope definitions.
## Completion rule
