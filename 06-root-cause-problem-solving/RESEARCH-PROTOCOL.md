# Research Protocol

**Status:** 🔴 RED — research workflow drafted; source quality and usefulness need validation.

## Purpose
Broaden investigation efficiently when local evidence is insufficient or repeated attempts fail.

## Source order
1. Official product/platform documentation and API references.
2. Official release notes, migration guides, and known-issue pages.
3. Maintainer-owned repositories, issue trackers, and reproducible bug reports.
4. Standards bodies and reputable technical references.
5. Community discussions as leads, verified against stronger evidence where possible.

## Procedure
- Search using the exact error, affected version, environment, and minimal reproduction.
- Record the source title, URL, publisher/maintainer, publication/update date, access/check date, applicable product/version, and exact claim supported.
- Distinguish official statements, user reports, hypotheses, and speculation.
- Compare at least one plausible alternative explanation before concluding when the evidence is ambiguous.
- Record URLs, relevant findings, version applicability, contradictions, and remaining unknowns; distinguish first-party facts from community reports and your own inference.
- Do not paste secrets or sensitive project data into external search services.
- Follow Section 05 approval rules before contacting maintainers, sending data externally, or purchasing access.
