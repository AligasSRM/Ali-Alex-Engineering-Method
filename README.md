### قاعدة بدء أي مشروع — إلزامية

قبل فتح مشروع جديد أو البدء بتنفيذه، يجب دراسة كيفية إنشائه من الصفر، وتحديد المشكلة والمستخدمين والوظائف الأساسية والتقنيات والتكاليف والأمان، ثم إعداد خريطة المعمارية والبيانات والتكاملات والأقسام ومعايير القبول وخطة الاختبارات والإطلاق. أنشئ مخططاً بصرياً للواجهة عند الحاجة، ولا تبدأ التنفيذ الكامل قبل اكتمال الخطة واعتماد القرارات الجوهرية.

إذا كان المشروع موجوداً مسبقاً، افحص حالته الفعلية أولاً ولا تفترض أنه جديد ولا تعِد بناءه تلقائياً.

### طريقة العمل

1. **بناء الهيكل والخريطة:** تحديد الأقسام والوثائق والمسؤوليات والاعتماديات وشروط القبول.
2. **تدقيق الأقسام معاً:** كشف الاعتماديات الناقصة والتناقضات والتكرار والمراجع القديمة.
3. **تنفيذ قسم تلو الآخر:** تنفيذ الوظيفة الحقيقية واختبارها وتوثيق الأدلة قبل الانتقال.
4. **تثبيت ما تم التحقق منه:** لا يُقفل القسم إلا بعد اجتياز شروط القبول والمراجعة واختبارات التراجع المطلوبة.

### معاني الحالات

- 🔴 **أحمر — لم يبدأ / متعطل:** العمل لم يبدأ أو يوجد عائق يمنع التقدم الآمن؛ يجب توثيق السبب والأثر.
- 🟡 **أصفر — هيكل أو عمل أولي:** التنفيذ أو الاختبار غير مكتمل.
- 🟠 **برتقالي — تكامل غير مكتمل:** يحتاج إلى إعداد أو اتصال أو إثبات تكامل.
- 🟢 **أخضر — تم التحقق:** اجتاز نطاق المرحلة معايير القبول والاختبارات المطلوبة بأدلة قابلة للفحص.
- 🔒 **مقفَل — مثبت:** اجتاز المرحلة مراجعة الإغلاق؛ لا يعاد فتحها إلا لسبب تقني موثق.

**لون الحالة وحده ليس دليلاً.** إنشاء الملفات أو نجاح البناء أو النشر وحده لا يثبت اكتمال المشروع أو تشغيله فعلياً.

### قواعد أساسية

- الجودة قبل السرعة، والفحص قبل التعديل، والتخطيط قبل البرمجة.
- تشخيص السبب الجذري قبل الإصلاح، وعدم تكرار المحاولات نفسها بلا معلومات جديدة.
- الأمان والخصوصية قبل التفعيل، وFail-Closed للوظائف الحساسة غير الجاهزة.
- لا ادعاء بنجاح اختبار أو تكامل أو نشر لم يحدث فعلياً.
- لا تغييرات كبيرة أو مدمرة أو مدفوعة أو حساسة دون الموافقة المطلوبة من علي.
- افصل أسرار وموارد وبيئات المشاريع، ولا تضف بيانات اعتماد وهمية.
- وثّق العوائق والقيود والاختبارات والدروس والخطوة التالية.
- فضّل الحلول المجانية المناسبة، وتحقق من حدودها وتكاليفها قبل الاعتماد عليها.

### الحالة الحالية

هذا المستودع يوثّق المنهج. وجود الوثائق لا يثبت وحده أن المنهج قد نجح في مشروع حقيقي؛ يجب إثبات ذلك بنتائج تنفيذ واختبارات فعلية.
